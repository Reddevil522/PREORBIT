Exception Handling

Try, catch, throw, and custom exceptions

What is an Exception?

An exception is an unwanted or unexpected event occurring during the execution of a program (at runtime) that disrupts the normal flow of instructions. Exception Handling is a mechanism to handle these runtime errors (like ClassNotFoundException, IOException, SQLException, etc.) so the normal flow of the application can be maintained.

Real-World Analogy: Flat Tire

You are driving to work (normal flow). Suddenly, you get a flat tire (an exception). If you don't know what to do, you're stuck (app crashes). But if you have a spare tire and know how to change it (exception handling), you fix the problem and continue driving to work (normal flow maintained).

Try-Catch Block

Java 
public class Main {
    public static void main(String[] args) {
        try {
            // Code that may raise exception
            int data = 100 / 0;
            System.out.println("This line will not execute");
        } catch (ArithmeticException e) {
            // Handling the exception
            System.out.println("Cannot divide by zero!");
        } finally {
            // Executes regardless of exception
            System.out.println("Finally block is always executed");
        }
        
        System.out.println("Rest of the code...");
    }
}

Checked vs Unchecked

  • Checked Exceptions: Checked at compile-time (e.g., IOException). You are forced to handle them using try-catch or declare them using throws.
  • Unchecked Exceptions: Checked at runtime (e.g., NullPointerException). They usually indicate programming logic errors.
  • Errors: Severe problems that a reasonable application should not try to catch (e.g., OutOfMemoryError).
